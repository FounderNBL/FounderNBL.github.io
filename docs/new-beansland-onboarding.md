# Welcome to New Beansland

This guide is for anyone invited to work inside the New Beansland production repository.

This is not a generic website, portfolio, or bookstore. It is a public-facing world with its own history, residents, institutions, stories, and internal system language.

## Before You Change Anything

Ask why something exists before replacing it. Some names, objects, routes, and files are part of continuity rather than decoration.

Do not assume a strange name is a mistake.

Do not expose private development material simply because you found it in a repository or workbench.

## Public New Beansland Personnel

The current public personnel layer is:

- **Beans / Tony Black — Founder & Voice of New Beansland**
- **Allen “A.B.” Blake — Mayor of New Beansland**
- **Professor Grey 🩶 — Applied Judgment, Value & Discernment**
- **Tobias “T.M.” Mansfield — Rules Examiner**

T.M. means Tobias Mansfield. It does **not** mean “Trouble Maker,” and T.M. is not a generic AI collaborator or continuity bot.

Public residents exist as people in New Beansland first. Their website responsibilities come from their in-world roles.

## Internal System Language

The code underneath the public site also uses NBL codenames. These names are infrastructure vocabulary, not a second public roster.

Read [NBL SYSTEM CODES](NBL_SYSTEM_CODES.md) before renaming unfamiliar internal components such as LOCKE, TA, TB, TEST, TS, NTB, ECHO, STILL, or TM.

## Playhouse vs Production

The private Playhouse is for development, testing, files, drafts, analysis, and experimentation.

The production repository contains approved public material.

Nothing should move from development into production automatically.

## Your Role

Build carefully. Preserve immersion. Favor maintainability over quick fixes. If two files appear to be duplicates, compare them before deleting either one and repoint every live reference before removing a confirmed duplicate.

Do not place private provider keys or secrets in this public repository.

## The Artifact Rule

If you see a diploma on the wall, do not automatically turn it into a button.

If you see a book, do not immediately expose its full text.

If you see an artifact, let the visitor experience it before explaining it.

**The artifact is not the button. The artifact is the experience.**

## Final Build Rule

**PLAYHOUSE THINKS. FOUNDER DECIDES. PRODUCTION PUBLISHES.**
