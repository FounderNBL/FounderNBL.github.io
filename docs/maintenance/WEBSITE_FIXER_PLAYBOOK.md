# NBL live website — coding Fixer design and repair contract

This is a source-context guide for a **real coding agent**, not a chatbot persona, separate from Beans. The authoritative evidence is current approved source on `main` and `config/nbl-website-green-baseline.json`. Never inspect Playground, Desk, University/NBLU, Grey/Virgo or games; do not read their repositories, visit their pages, or change their code. Website source has references to held areas; those are not inspection targets.

## NBL's actual CSS language — use, do not replace

From the live website's `nbl-world-header.css :root`:
- `--nbl-world-bg: #02060b` (ink background)
- `--nbl-world-panel: #071421` (navy)
- `--nbl-world-gold: #d6a14b` (NBL gold)
- `--nbl-world-gold2: #f0c56f` (gold highlight)
- `--nbl-world-cream: #f4ead8` (cream text)
- `--nbl-world-soft: #cfc3ad` (soft neutral)
- `--nbl-world-line: rgba(214,161,75,.30)` (subtle gold border)

Messenger's separate `messenger/messenger-skin.css` also defines its own `--night`, `--navy`, `--gold`, `--gold2`, `--cream` and `--surface` variants. Maintain component-specific tokens where they already exist; **do not globally restyle the site to force consistency**.

NBL public World cards should preserve approved **4:3 card frames**, **`object-fit: contain`** for full uncropped images, mobile single-column layout for the social cards, and existing focus/keyboard affordances. Never invent new art or use private raw GitHub URLs on the public page. Existing Pulse/Messenger approved art and hashes are in the GREEN contract.

The existing homepage and header are the visual reference. Approved screenshots belong in review artifacts; screenshots generated by a bot are evidence, **not** automatically a new Founder-approved design baseline.

## Single-run repair contract

1. Read the **specific** failing GREEN receipt; require a reproducible scoped source mismatch. A bot challenge, missing credentials, customer data, or unrelated failure is not a repair target.
2. Search the **versioned approved repair lessons**, limited to this website and this symptom. A lesson is a precedent, not authority.
3. Study only the affected approved files and their imported style tokens. Do not read unrelated project source or turn broad refactoring into a 'fix'.
4. Edit the **smallest source change** that removes the reproduced failure. Add or adjust a regression test if necessary. Do not remove tests merely to get green.
5. The deterministic diff policy independently rejects changes to protected source, workflows, billing, roles, keys or unknown files.
6. Independent code tests and browser regression run on the candidate patch in the **same GitHub workflow run**. Failure or skipped validation is not PASS.
7. Save a versioned, evidence-linked lesson only for a verified repair. An approved/merged PR makes that lesson available to later runs. A rejected patch is not learned as a successful fix.
8. Create a **draft PR for Founder review**. Do not merge or deploy, spend money without configured cap, or alter Beans.

**Provider/credential boundary:** The coding Action requires a site-repository available OpenAI API credential and explicit enablement. NBL's existing Beans repository credentials are not silently inherited by this website. Do not dump, copy, or embed keys in code. No model calls on a healthy scheduled check.

**Current acceptance limit:** The agent must still complete an actual self-directed failing-source -> code-edit -> independent-retest -> draft-PR proof before it is called operational. A Biome formatting fixture is insufficient proof.
